durability_gate: **RAISED AND UNRESOLVED.** Per canonical algorithm step 2, this gate is resolved first and may not be outvoted by the other three lenses.

**What could be destroyed.** Deterministic Go code that executes an irreversible action — workspace or resource deletion, cascade deletion of dependent entities, state resets that discard history, permission revocation — executing on a rule that is subtly wrong, in parallel across the fleet, at machine rate. The concrete named scenario: a rule keying on last-*modified* rather than last-*activity* time deletes 10,000 workspaces in one hour across 1000 instances; every deletion logs as intended behavior, so no alarm fires and no diagnostic flags it; discovery takes 7 days, by which time backup retention has expired. The loss is permanent. Blast radius is fleet-wide by construction, because the whole point of compiling the decision is to run it everywhere without a model in the loop. Durability quantifies the amplification against today's per-agent LLM-mediated blast radius at 100×–10000×.

**Which objections are unresolved.** Two are graded BLOCKING by the durability lens itself:
- **Recovery paths are unexercised.** The epic asserts recovery but offers no evidence any restore has been performed. Does the backup exist; can it be restored; does restoration take seconds or days; can restored data be reconciled with state that kept evolving after the deletion — all four unanswered.
- **The gating principle is inverted.** The epic permits destructive actions to be gated by *absence of evidence of danger* rather than *affirmative evidence of safety*. This is backwards, and it is a property of the epic's text, not of any candidate — so it will be inherited by every migration the program produces until the text is fixed.
Two more are graded RESOLVABLE but are not yet resolved: blast-radius scaling is unaddressed anywhere in the epic, and there are no confidence gates for edge cases, so deterministic code has no "I'm not sure" path and will act on inputs it should have escalated.

**What evidence would clear it.** Each item below is a structural precondition, not a promise:
1. A **mutation class** recorded as a required, machine-checked field on every candidate bead — `read-only` / `reversible-write` / `irreversible` — with the pipeline refusing to advance an `irreversible` candidate that lacks the remaining items. Classification is not a reviewer's judgment call made from memory.
2. **A restore actually performed and documented** for each data class an `irreversible` candidate can touch: what was restored, how long it took, what was reconcilable and what was not. One executed restore, not a scheduled intention.
3. **The epic's gating sentence rewritten** so destructive actions require affirmative evidence of safety, and the rewrite landed in gt-ks3j's DESIGN field where every candidate inherits it.
4. **A shadow-mode comparison harness that exists and runs** — deterministic path and model path on the same input, divergences logged and countable — with a stated agreement threshold that must be met before any `irreversible` candidate executes for real.
5. **A kill-switch per migrated decision, tested by being thrown**, reverting to the model-mediated path in seconds, with the model path demonstrably still present and not retired.
6. **A staged-rollout gate the pipeline enforces** (1% → 10% → 100%), with a named abort criterion and an automated abort, so promotion is not an operator decision made under time pressure.
7. **Grace-period soft-delete for irreversible operations**: mark, wait, allow a human to halt, then finalize — with the waiting period enforced in code.
8. **Anomaly detection on destructive-action rate**, alarming on a spike, wired to something a person actually sees.
Items 1–3 clear the two BLOCKING objections. Items 4–8 clear the two RESOLVABLE ones. Until 1–3 exist, the gate stands regardless of what the other three lenses conclude.

What is established: for the *existing* control loop, retry backoff tops out at approximately 17 minutes (10 retries, exponential) and hung-session detection fires at a hardcoded 30 minutes with no graduated escalation. For the *proposed* escalation architecture, the state lens established that deterministic→LLM→deterministic→LLM has no maximum depth, no loop detection, and no give-up state, and that a stall in that loop is silent if the model's reasoning is consistent while the software's logic is unchanged. Reliability separately found no dispatch backpressure of any kind, so a fan-out is unbounded in width as well as in depth. **A bound cannot be stated because none exists in the design and no lens produced one.** This is itself a decision input required from the human, and it is the specific deliverable the reliability leg owed and did not deliver.

silent_worst_path: **How this destroys something while nobody is watching.** The epic's premise is that a decision proven predictable can be compiled and thereafter executed without a model in the loop. The model in the loop is currently also the system's only semantic check. Remove it and the system retains its syntactic checks — did the code run, did it error, did throughput hold — and loses the only thing that was ever asking whether the decision was *right*.

So: a rule is compiled from a decision that was predictable across every case anyone observed. It is deployed fleet-wide. It is subtly wrong on a class of inputs nobody observed — the wrong timestamp field, an edge case that looks expected but is semantically different, a job class that silently sorts to the bottom. The code executes correctly and logs correctly, so every diagnostic reports health, because the diagnostics were built to detect *failure* and this is not a failure. It is a success at the wrong thing. Parallel execution multiplies it by the fleet before any human is in a position to look. Durability's version ends with 10,000 workspaces deleted, backups expired, data gone permanently, discovered after 7 days. Operability's ends with 15% of jobs systematically deprioritized for 3 weeks, discovered by a user complaint. State's ends with a stale cached decision executing against fresh state after a crash-restart, with no reconciliation store to catch the divergence because there are three sources of truth and no authority among them.

Three lenses, working blind, reached this same shape from three different directions. The mechanism is the same in each: **the system's confidence in a compiled decision is inherited from a period when a model was checking it, and that confidence is not revalidated after the model is removed.** Nothing in the epic revalidates it.

structural_vs_procedural: Per canonical algorithm step 4 — a mitigation must be structural unless structure is genuinely impossible, and discipline is not a control.
**Structural — accepted:** mutation-class as a required machine-checked bead field; shadow-mode comparison harness with a countable divergence metric; per-decision kill-switch reverting to the model path; escalation depth counter with a terminal state and an explicit give-up condition; escalation-rate metric with a threshold alarm; grace-period soft-delete enforced in code; staged-rollout promotion gates with automated abort; named states for every LLM-reasoning and Go-deterministic condition with per-state crash-recovery invariants; a single authoritative reconciliation store replacing the current three sources of truth; a race-prevention mechanism for concurrent decisions; anomaly detection on destructive-action rate.
**Procedural — rejected, with the structural replacement named:**
- Operability's "add observability as a 9th point to the analysis" → **rejected as written.** A checklist item is a reminder. Replacement: a required, machine-checked field on the candidate bead that the pipeline refuses to advance without. The *content* of the ask is correct and is retained as a condition; only the enforcement mechanism is rejected.
- Durability's "require written durability sign-off before implementation" → **rejected.** Replacement: the mutation-class field plus the gate items above, checked by the pipeline. A signature records that someone looked; it does not record that anything was true.
- Durability's "exercise recovery paths quarterly" → **rejected as a calendar commitment, retained as a gate.** Structure is genuinely partially impossible here: a full restore of every data class cannot be continuously exercised at reasonable cost. So the *test* may be periodic, but the *staleness check* must be structural — the pipeline reads the timestamp of the last executed restore for the affected data class and blocks an `irreversible` candidate when it is stale. That converts "we will remember" into "the machine refuses."
- Any mitigation of the form "operators will monitor the rollout" → **rejected outright.** The entire silent-worst-path finding is that operators looking at healthy dashboards see health. Attention is not a control against a failure mode defined by looking normal.
